01 — a dor que a gente vai resolver

Todo dia é o primeiro dia dele

Imagine contratar alguém brilhante, que resolve qualquer problema — mas que acorda todo dia sem lembrar de nada: nem do projeto, nem das decisões de ontem, nem de você.

🔁 Você reexplica tudoStack, estrutura de pastas, padrão de nomes, como rodar os testes. Toda. Conversa. Nova.

↩️ Ele desfaz o que você decidiuAquela escolha que você fez na terça é revertida na quinta, com toda a confiança do mundo.
😤 Você cansa antes deleRepetir contexto é um trabalho chato que não aparece em lugar nenhum — e você paga por ele todo dia.
🎯 A saída não é escrever prompts maiores. É tirar o contexto da sua cabeça e colocar no repositório — num formato que o agente leia sozinho, sem você pedir. É disso que a aula de hoje trata.
02 — antes de digitar qualquer coisa

O Cursor não é uma ferramenta.
São quatro.

Abra o chat com Ctrl/Cmd + I e alterne entre os modos com Shift + Tab. Escolher o modo errado é a causa mais comum de sessão que descarrila — e quase ninguém repara nisso.

💬Asksó leitura
Responde perguntas e não toca em arquivo nenhum. Consegue rodar comandos de leitura no terminal (checar um commit, listar arquivos) para embasar a resposta.
use quandoVocê quer entender antes de mudar: "o que esse módulo faz?", "onde isso é chamado?", "quais regras estão ativas agora?"
🗺️Planplano em disco
Investiga e devolve um plano de ação antes de escrever código. O plano vira um arquivo no disco que você pode editar como qualquer outro — e é aí que está o valor.
use quandoA tarefa toca mais de um arquivo, ou quando você quer discordar do caminho antes de existirem 200 linhas para revisar.
⚡Agentpadrão
O modo autônomo: lê, escreve, roda comandos e itera sozinho até terminar. É o que a maioria usa o tempo todo — inclusive quando não deveria.
use quandoO caminho já está claro. Executar é diferente de decidir: o Agent é ótimo executor e um decisor apressado.
🔬Debuginstrumenta
Em vez de adivinhar a causa lendo o código, ele instrumenta a aplicação com logs em tempo de execução, reproduz o bug e trabalha em cima da evidência.
use quandoO bug resiste a duas tentativas do Agent. É o sinal de que falta observação, não mais palpite.
Cuidado com o Auto-run

Nas configurações do Agent existe o Auto-run (o antigo "Yolo mode"): o agente executa comandos de terminal sem pedir confirmação. Útil, e perigoso na mesma medida. Se for ligar, configure a lista de comandos permitidos — não deixe aberto.

02 — como os modos se encaixam

O erro é começar direto no Agent

Você joga um pedido grande no Agent, e noventa segundos depois está olhando um diff que tocou quatorze arquivos — metade deles errados. O problema quase nunca foi o prompt: foi pular as duas etapas anteriores.

🧵 /multitask e subagentes

Na janela de agentes, o comando /multitask quebra uma tarefa grande em subagentes que rodam em paralelo. O detalhe que interessa aqui: cada subagente tem a própria janela de contexto, e só o resumo final volta pro agente pai — que fica livre e responsivo.

Vamos voltar nisso a fundo numa aula dedicada a subagentes. Hoje, só saibam que existe.

🔁 E nas outras ferramentas?

Os nomes mudam, a ideia não. O Claude Code tem um modo de planejamento e uma permissão de só-leitura; o Codex e outros CLIs trabalham com níveis de autonomia parecidos.

O que vocês precisam levar não é a tecla de atalho — é o hábito de perguntar "qual modo isso pede?" antes de digitar. Esse hábito é portátil.

03 — o que vamos construir

O projeto: dq

Um CLI que recebe um CSV e reporta problemas de qualidade nos dados. Duas aulas para construir. Mas atenção: o projeto não é o assunto — ele é a desculpa.

😖 A dor real

Você recebe uma planilha "pronta". Carrega, roda a análise, manda o relatório pro time.

Três horas depois descobre que a coluna preco_unitario tinha "R$ 1.234,56" no meio dos números.

Inspeção manual não escala: você olha as primeiras 20 linhas, parecem boas, e segue em frente.

🎯 O que ele vai fazer

$ dq data/vendas.csv ✗ nulos 13 valores faltando ✗ duplicatas 3 linhas repetidas ✗ tipos 8 valores fora do tipo ✓ formato nenhum problema

Três checks. Um relatório no terminal. Nada além disso — de propósito.

🧪 O arquivo data/vendas.csv tem 71 linhas e defeitos plantados de propósito. Alguns são óbvios. Outros você só acha se procurar. Ele já está no repositório que vocês receberam.
03 — critério de escolha

Por que um projeto propositalmente simples?

Se o projeto fosse difícil, a aula viraria uma discussão sobre pandas. O código aqui é banal justamente para que sobre atenção para o processo.

🧠 Domínio que vocês já dominamNinguém precisa aprender o negócio. Carga cognitiva zero no problema, 100% no método.
🧩 Tem camadas naturaisLer → validar → relatar. A conversa sobre estrutura de pastas nasce do problema, não de doutrina.
➕ É trivialmente extensível"Adicione um check novo" é o teste perfeito: ou o agente segue o padrão que vocês definiram, ou não segue. Sem meio-termo.
⚡ Roda em qualquer máquinaSem banco, sem API key, sem docker. O tempo de aula vai pro que importa.
💭 No fim das duas aulas, o que vocês levam não é um validador de CSV — é um método que funciona em qualquer repositório que vocês tocarem depois.
04 — o conceito central

Prompt é o que você digita.
Contexto é tudo que ele vê.

Quando você aperta Enter no Cursor, o modelo não recebe só a sua frase. Ele recebe um pacote — e a sua frase é a menor parte dele.

🧠 Context engineering é decidir o que ocupa esse espaço — e quando. Não é escrever instruções melhores; é gerenciar um recurso escasso.
05 — a ferramenta

Agent rules: instruções que entram sozinhas

São arquivos markdown, versionados no repositório, que a ferramenta injeta no contexto automaticamente. Você não cola, não menciona, não lembra. Eles simplesmente estão lá.

😩 Sem agent rules
💬
Você digita o contexto"Usamos pandas, os testes ficam em tests/, não crie utils.py..."
🧠
Depende da sua memóriaVocê esquece uma restrição, o agente viola, você corrige depois.
👤
Não escala pro timeO contexto está na sua cabeça — não no repositório.
🔀
Cada um tem seu jeitoTrês pessoas, três padrões, um código que não parece do mesmo projeto.
VS
📜 Com agent rules
⚡
O contexto já está no pacoteToda conversa começa com as convenções carregadas.
🔒
As restrições não somemO "não faça X" continua valendo na mensagem 40.
👥
Vale pro time inteiroEstá versionado. Quem clonar o repo herda o contexto.
🔍
Vira código revisávelMudou uma convenção? Abre PR. Discute. Aprova.
💭 O nome técnico é "agent rules", mas o jeito mais honesto de pensar nisso é: é o onboarding do seu projeto, escrito uma vez, executado automaticamente, para sempre.
06 — o mesmo conceito, nomes diferentes

Um conceito. Três dialetos.

Cada ferramenta inventou seu próprio nome para a mesma ideia. Isso confunde — mas a lógica é sempre a mesma: markdown no repositório que entra no contexto sozinho.

CLAUDE.md
Convenção da Anthropic · Claude Code
Modelo de memória em camadas: um arquivo global na sua home, um na raiz do projeto, e opcionalmente um por subpasta. Mais rico que o padrão aberto, mas só o Claude Code entende essa hierarquia.
AGENTS.md
Padrão aberto · quase todo mundo lê
Proposto pela OpenAI em agosto de 2025 e doado à Linux Foundation em dezembro do mesmo ano. Markdown puro, sem configuração. Lido nativamente por Cursor, Codex, Copilot, Gemini CLI, Aider, Windsurf e outros.
.cursor/rules/*.mdc
Específico do Cursor · o nosso caso
Markdown com um bloco de configuração no topo. É o único formato que permite dizer quando a regra deve entrar no contexto — e é por isso que ele existe.
🧭 A regra prática: se você só adota um, adote o AGENTS.md — é o de maior alcance. Os outros dois são especializações que você adiciona quando precisa do que eles fazem de diferente.
07 — a diferença que importa no Cursor

.md vs .mdc

MDC significa Markdown with Configuration. É markdown normal com um bloco YAML no topo — e esse bloco é a diferença inteira.

AGENTS.md — MARKDOWN PURO
# Convenções do projeto Todo check devolve um CheckResult. Os testes ficam em tests/. Não crie utils.py.

Sem metadados. Carregado por inteiro, sempre, em toda requisição. Simples e portátil.

CHECKS.MDC — COM CONFIGURAÇÃO
--- description: Padrão para escrever checks globs: ["src/dq/checks.py"] alwaysApply: false --- # Como escrever um check Assinatura: check_x(df) -> CheckResult

Os três campos do topo decidem quando essa regra entra no contexto. Fora disso, é markdown igual.

⚠️ Um .md dentro de .cursor/rules é ignoradoDentro dessa pasta, o Cursor só lê arquivos .mdc. Trocar a extensão é o erro mais comum de quem está começando.
🗑️ O .cursorrules da raiz é legadoAinda é lido por compatibilidade, mas é ignorado no modo Agent e não recebe features novas. Metade dos tutoriais no Google ainda ensina ele — desconfie.

08 — o cenário real

E se eu uso vários modelos?

Cursor de manhã, Claude Code à tarde, Codex numa tarefa específica. É o normal hoje. E é aqui que quase todo mundo comete o mesmo erro.

O erro: duplicar

  • Você copia as mesmas convenções em CLAUDE.md, AGENTS.md e num .mdc
  • Funciona lindamente por duas semanas
  • Alguém muda uma convenção e atualiza só um dos três
  • Agora os arquivos se contradizem — e o agente obedece o errado
  • Regra contraditória é pior que regra nenhuma: sem regra ele pergunta, com regra errada ele age com confiança

A saída: fonte única + ponteiro

  • AGENTS.md é a única fonte de verdade — todo o conteúdo mora nele
  • CLAUDE.md vira um arquivo de duas linhas apontando para ele
  • Os .mdc guardam só o que é específico do Cursor: o escopo por glob
  • Uma mudança, um arquivo, um lugar para revisar no PR
  • Se um dia você trocar de ferramenta, o contexto vai junto
CLAUDE.MD INTEIRO, NO MODELO DE PONTEIRO
# Instruções do projeto As convenções deste repositório estão em @AGENTS.md. Leia esse arquivo antes de qualquer tarefa. Não duplique nada aqui.
09 — o que escrever de verdade

O que entra e o que não entra

Entra

  • Comandos — como rodar testes, lint, o projeto
  • Mapa de diretórios — o que vive onde, e por quê
  • Convenções não óbvias — as que ele erraria se chutasse
  • O que NÃO fazer — restrições explícitas, a seção mais subestimada
  • Como testar — o padrão de teste que o projeto segue

Não entra

  • O que dá pra ler do código — ele consegue abrir o arquivo sozinho
  • Requisitos de produto — isso é outro documento, carregado sob demanda
  • Tutorial de linguagem — ele sabe Python melhor que a gente
  • Histórico e decisões antigas — vira ADR (aula futura)
  • Qualquer coisa que muda toda semana — envelhece e passa a mentir
🎯 O teste dos 10 minutos: se um dev sênior entrasse no time hoje, o que você contaria a ele nos primeiros 10 minutos que ele não descobriria sozinho lendo o código? Isso — e só isso — é o seu AGENTS.md.
09 — a armadilha

Mais regra ≠ mais obediência

O caminho natural de quem descobre agent rules é escrever um arquivo de 800 linhas com tudo que já deu errado. Isso piora o resultado, e por dois motivos ao mesmo tempo.

💸 Custo

Cada token de regra sempre-ligada é reenviado a cada mensagem. Um AGENTS.md gigante come a janela antes mesmo de você fazer a primeira pergunta — e empurra pra fora justamente o código que ele precisava ler.

🌫️ Diluição

Cinquenta regras de igual peso não têm peso nenhum. Quando tudo é importante, nada é prioridade — e o modelo escolhe qual seguir por conta própria. Cinco regras que ele obedece valem mais que cinquenta que ele ignora.

📏 Mantenha curtoCada arquivo de regra abaixo de ~500 linhas; o conjunto sempre-ligado, bem menor que isso.
✂️ Fatie por escopoQuando o arquivo engorda, não corte conteúdo: mova o que é específico para um .mdc com glob.
🌱 Destile do atritoNão escreva as regras de antemão. Escreva quando o agente errar — aí você sabe que ela é necessária.
🗑️ Delete sem dóRegra que descreve algo que não existe mais é pior que nenhuma regra. Revise junto com o código.

PASSO 2 Criar o AGENTS.md na raiz ✍️ você escreve ▼

Este arquivo é escrito por vocês, não gerado. É curto de propósito: só o que o agente erraria se chutasse.

AGENTS.mdmarkdown
# AGENTS.md ## O que é este projeto `dq` é um CLI que lê um CSV e reporta problemas de qualidade nos dados. Não corrige nada, não escreve arquivos — só lê e relata. ## Comandos pytest -q # roda os testes dq data/vendas.csv # roda o CLI ## Estrutura src/dq/cli.py → argumentos e impressão. Sem regra de negócio. src/dq/checks.py → todas as validações. tests/ → um arquivo de teste por módulo. data/ → somente leitura, nunca sobrescrever. ## Convenções obrigatórias - Todo check devolve um `CheckResult` (dataclass com nome, ok, total, detalhe). Nunca `bool`, nunca string solta. - Checks são registrados no dicionário `CHECKS`, nunca em if/elif. - Toda função de check recebe `df: pd.DataFrame` e devolve `CheckResult`. Sem parâmetros posicionais extras. - A saída vai para stdout. Não escreva arquivo de relatório. - Nada de `print` dentro de `checks.py`. Quem imprime é o `cli.py`. ## O que NÃO fazer - Não adicione dependências. `pandas` e `pytest` bastam. - Não crie `utils.py`, `helpers.py` ou `common.py`. - Não escreva nem modifique nada em `data/`. - Não refatore código fora do pedido atual.
O teste dos 10 minutos

Só entra aqui o que vocês contariam a um dev sênior novo nos primeiros 10 minutos e que ele não descobriria sozinho lendo o código. Se dá pra ler do código, não escrevam.

PASSO 3 Criar a primeira regra escopada ✍️ você escreve ▼

Crie a pasta .cursor/rules/ e dentro dela o arquivo abaixo. Repare no frontmatter: ele diz que essa regra só entra quando o agente tocar nesses dois arquivos.

.cursor/rules/checks.mdcmdc
--- description: Padrão para escrever e registrar checks de qualidade globs: ["src/dq/checks.py", "tests/test_checks.py"] alwaysApply: false --- # Como escrever um check ## Assinatura def check_<nome>(df: pd.DataFrame) -> CheckResult Sem parâmetros extras. Se precisar de configuração, use valor padrão nomeado — nunca segundo posicional. ## Passos ao adicionar um check 1. Escreva a função em `src/dq/checks.py`. 2. Registre no dicionário `CHECKS` no fim do arquivo. 3. Escreva o teste com um DataFrame construído na mão. 4. Não toque em `cli.py` — ele já itera sobre `CHECKS`. ## Regras do CheckResult - `ok` é True quando NADA foi encontrado. - `total` é contagem de ocorrências, não de linhas. - `detalhe` é uma frase curta em português, sem quebra de linha.
Erro mais comum

Salvar como .md. Dentro de .cursor/rules/ o Cursor só lê .mdc — e não avisa quando ignora. YAML também é sensível a indentação: um globs mal escrito nunca dispara, silenciosamente.

Aqui "engenharia de contexto" deixa de ser jargão. Vamos ver a regra entrando e saindo do contexto conforme o arquivo aberto.

1 · abra src/dq/cli.py e pergunteprompt
Quais regras estão ativas nesta conversa agora? Liste pelo nome do arquivo.
2 · agora abra src/dq/checks.py e pergunte o mesmoprompt
E agora? Quais regras estão ativas?
O resultado

PASSO 6 Executar o plano ⚡ Agent ▼

Com o plano aprovado, o Agent vira só um executor — que é onde ele é excelente. O resultado deve ficar assim:

src/dq/checks.pypython
from dataclasses import dataclass import pandas as pd @dataclass class CheckResult: nome: str ok: bool total: int detalhe: str def check_nulos(df: pd.DataFrame) -> CheckResult: contagem = df.isna().sum() faltando = contagem[contagem > 0] total = int(faltando.sum()) if total == 0: return CheckResult("nulos", True, 0, "Nenhum valor faltando.") colunas = ", ".join(f"{col} ({n})" for col, n in faltando.items()) return CheckResult("nulos", False, total, f"Valores faltando em: {colunas}") CHECKS = { "nulos": check_nulos, }
src/dq/cli.pypython
import argparse import pandas as pd from dq.checks import CHECKS def main() -> None: parser = argparse.ArgumentParser(description="Valida a qualidade de um CSV.") parser.add_argument("caminho") args = parser.parse_args() df = pd.read_csv(args.caminho) for nome, check in CHECKS.items(): r = check(df) simbolo = "✓" if r.ok else "✗" print(f"{simbolo} {r.nome:<12} {r.detalhe}")
Leiam o diff inteiro

Não aceitem só porque rodou. Import que ninguém pediu, função que nunca é chamada, arquivo criado fora do combinado — é aqui que aparece.

PASSO 7 Rodar e validar de verdade ⌨️ terminal ▼
terminalbash
pytest -q dq data/vendas.csv

A saída esperada aponta valores faltando em várias colunas. O CSV tem 71 linhas com defeitos plantados de propósito — se o check disser que está tudo certo, o check está errado.

Curiosidade que vale 30 segundos

Uma das linhas tem a string N/A no preço. O pandas.read_csv converte isso em nulo sozinho, sem avisar. O check de nulos acha; um futuro check de tipos nunca vai ver. A ferramenta tomou uma decisão por você — e não te contou.

11 — o que costuma dar errado

Cinco armadilhas na primeira vez

📄 Salvar como .md dentro de .cursor/rulesO arquivo é simplesmente ignorado, sem aviso nenhum. Você acha que a regra está ativa e ela nunca esteve.
🌍 Glob que casa com tudo**/* transforma uma regra escopada numa regra sempre-ligada. Se o glob pega tudo, você perdeu o motivo de ter usado .mdc.
🤷 Regra vaga"Escreva código limpo" não é uma regra — é um desejo. "Todo check devolve CheckResult" é uma regra: dá pra verificar se foi seguida.
📋 Copiar template da internetRegra que não nasceu de um problema seu descreve um projeto que não é o seu. Ocupa contexto e não protege nada.
🤐 E a quinta: assumir que o agente leu Ele não avisa quando ignora uma regra. Na dúvida, pergunte direto: "quais regras estão ativas nesta conversa?". Leva cinco segundos e evita meia hora de confusão.
